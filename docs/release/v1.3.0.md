# repofit v1.3.0

Engine release that carries corpus-default 2.0.0. Additive evidence and SDK
changes, opt-in probes, retired-id warnings and new judge defaults. No SDK
removals; corpus-default 1.x keeps working against this engine.

## Changes

- **`agent_config` evidence v2.** The subsystem now enumerates instruction
  files (depth, bytes, lines, hash, link target, `@include` lines), skills
  under any `skills` directory (frontmatter, body length, evals and
  references) and harness config files, alongside the existing `guidance`
  list. New SDK types: `InstructionFile`, `SkillFile`, `SkillFrontmatter`,
  `HarnessConfigFile`, `LinkInfo`, `SizeStatsEvidence`, `SizeStatsFile`.
  `node_package.raw` exposes the parsed manifest.
- **Fixture helper.** `buildAgentConfigEvidence(tree)` builds v2 evidence
  from an in-memory file tree, exported from the SDK for corpus authors.
- **Opt-in probes.** A probe may declare `optIn: true`; it runs only when its
  id is named in `gate.include`, `--include`, or selected with `--probe`.
  `--include` and `gate.include` accept probe ids as well as tiers.
- **Retired-id warnings.** A corpus may export `retired`, mapping removed
  probe ids to their replacement. A config that disables, waives or includes
  an unknown id gets a warning on stderr instead of silently matching
  nothing.
- **Judge defaults.** The reasoned tier defaults to `claude-haiku-5-5` and
  `gpt-5.4-mini`. Override with the existing model options; the judge cache
  keys on the model, so first runs after upgrading re-judge.
- **Reporter fix.** Minimal and HTML reporters label predicate probes by the
  scored direction, so a negative-direction probe no longer shows `PASS` for a
  finding.

## Upgrading

```bash
npm install --save-dev @esbenwiberg/repofit@1.3.0 @esbenwiberg/corpus-default@2.0.0
```

See [corpus-default v2.0.0](./v2.0.0.md) for the probe changes and the
baseline re-accept.
