# corpus-default v2.2.0

One probe learns to read churn
([esbenwiberg/repofit#24](https://github.com/esbenwiberg/repofit/issues/24)).
No id, band or dimension changes. Requires `@esbenwiberg/repofit` 1.4.0 for
the per-commit file lists; against an older engine the probe still runs and
reports every high fan-in module as `info`.

2.1.0 was tagged in git but never reached npm, so this is also the first
published release carrying its three probes (`agent.nested-guides-routed`,
`agent.generated-paths-protected`, `agent.untrusted-content-framed`); see
`docs/release/v2.1.0.md`.

## Changes

- **`arch.coupling-hotspots` 1.1.0.** Fan-in is weighted by churn. A module
  imported by more than 20 local modules is a `warn` only when it also
  changed in more than 10% of the last 100 commits and at least 5 times;
  below that it is listed as `info` with its fan-in and touch counts so the
  hub keeps its name in the inventory. A layer's value types and barrels
  (49 importers, 5 touches in 174 commits on the field-study repository)
  no longer zero the probe on their own: three stable hubs score 80 instead
  of 20, and three churning hubs still score 20. With fewer than 20 commits
  of history (a shallow CI clone, a new repository) churn is unknown and
  fan-in is reported as `info` with the window size. Fan-out and cycle
  findings are unchanged. The probe moves to the `historical` tier and
  reads `commit_history`; it still runs by default.

## Upgrading

```bash
npm install --save-dev @esbenwiberg/corpus-default@2.2.0
```

Then bump the corpus pin in `repofit.config.json` to `2.2.0`. Scores can only
rise or stay; re-accept the baseline with `repofit check --accept` if the
probe moves on your repository. Give CI checkouts enough depth (20 commits
or more) for churn to be measured, or every hub reads as `info`.
