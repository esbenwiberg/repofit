# repofit v1.4.0

Engine release that carries corpus-default 2.2.0. One additive evidence
change; no SDK removals, corpus-default 2.1 keeps working against this
engine.

## Changes

- **Commits carry the paths they touched.** `CommitRecord` gains an optional
  `files: string[]`, filled by one `git log --name-only` pass over the same
  100-commit window (no per-file `--follow`). A probe can now measure
  per-file churn, which is what `arch.coupling-hotspots` 1.1.0 uses to tell
  a stable hub from a hot one. Fixtures that omit `files` still work; a
  probe reading it must treat an absent list as unknown churn, not zero.
  Rename detection is not applied: a path renamed inside the window counts
  under each name separately. A shallow clone's grafted root lists every
  file as touched, so churn from a depth-N checkout is inflated by one
  touch per file.

## Upgrading

```bash
npm install --save-dev @esbenwiberg/repofit@1.4.0
```

No config or baseline changes.
